# Phase 21 设计稿：WinUI 壳视觉与交互打磨（三栏 IA + 令牌化 + 丰富动效）

> 状态：待用户审阅｜日期：2026-10-07｜基线：`e67a29c`（master，工作树干净，180 测试绿）
> 上游：Phase 20 决策门结论 = **续投 WinUI**（`docs/PHASE20-COMPARISON.md` §5）；本阶段是"继续投入"的第一段
> 后续：本稿经用户审阅后进入 writing-plans 出实施计划

## 0. 一句话

把 WinUI 壳从"能用的切片"打磨成"像样的播放器"：**只做视觉与交互，不加任何功能**——换三栏信息架构、引入设计令牌、补齐六态与无障碍、上"丰富"档动效，并把 `MainWindow` 拆成四个可独立读的 UserControl。

## 1. 目标与非目标

### 目标（G）

| # | 目标 | 可验性 |
|---|---|---|
| G1 | 三栏常驻 IA（左导航 / 中列表 / 右信息栏 + 整条底栏），左右两栏可折叠 | 真机清单：折叠往返、<960px 自动收起 |
| G2 | 视觉令牌化（间距 / 排版 / 圆角 / 颜色 / 时长），颜色一律引用主题资源、**无写死色值** | grep 壳内 `#RRGGBB` 为 0；清单逐项对表 |
| G3 | 六态齐备（默认 / 悬停 / 按下 / 选中 / 焦点 / 禁用） | 清单逐项；今天"禁用/焦点"基本没有 |
| G4 | 键盘与无障碍补齐（Tab 顺序、方向键细步进、空格播放暂停、UIA 名称） | 清单逐项（键盘项用户手测） |

### 非目标（本阶段**明确不做**，全部留给"功能补齐"阶段）

表头排序（表头本阶段是**静态标签行**）、列表 ▶ 当前曲标记、频谱可视化、拖拽（外部入队 / 队列重排）、文件与文件夹对话框、EQ、设置对话框、播放列表导入导出、音量与静音、上一首/下一首、随机/循环、窗口几何持久化、折叠状态持久化、Windows 应用日志/崩溃出口、MSIX 打包、WPF 侧任何改动。

## 2. 决策记录（本轮澄清的 7 条，含被否方案）

| # | 决策 | 被否方案与理由 |
|---|---|---|
| D1 | 范围＝**只做视觉与交互打磨**，不加功能 | 否"一次性全量对齐"（含频谱重写/拖拽 API 差异，阶段过大）；否"只修硬伤"（用户要的是"细化界面"） |
| D2 | 验收＝**逐项清单**（先出清单→用户划增→按清单验） | 否"对标参考应用"（要挑参考对象且解释权模糊）；否"只修硬伤" |
| D3 | IA＝**B 三栏常驻** | 否 A 精修三区（信息面板/频谱将来无位置）；否 C 大封面侧栏（歌单导航变弱、与 WPF 习惯差最远）；否 D 命令栏式（命令栏与底栏右槽今天都是空占位，显得"计划比功能多"） |
| D4 | 右栏＝**静止信息面板**（封面 + 标题/艺术家/专辑/时长） | 否"只做外壳"（空右栏在视觉上最难做像）；否"只验证折叠"（验证价值最小）。跨线说明：§3 差距表里"曲目信息面板 ❌"的**静止部分**本阶段做，动态部分（频谱）仍属功能阶段 |
| D5 | 密度/排版＝**衡**（行高 36 / 正文 13.5 / 圆角 8 / 边距 12–16） | 否"紧"（观感收益最小）；否"宽"（一屏 11 首，翻找变慢） |
| D6 | 依赖＝**允许 `CommunityToolkit.WinUI`** | 否"不引新依赖"（动效代码更笨）；否"先不引卡住再说"（本阶段动效项多，预期会卡）。版本由实施计划**实测钉死**，不猜；若不兼容则退回 WASDK 自带能力并记账 |
| D7 | 动效＝**丰富档，9 项全要** | 否"适度"（用户要观感）；否"极简"（会显得比 WPF 还硬）。9 项见 §6 |

## 3. 架构与工程改动

### 3.1 文件结构（壳侧为主；`D-player.Core` 与 WPF 壳**一个字节不动**）

```
D-player.WinUI/
├─ App.xaml(.cs)                      ← 合并 Theme/ 资源字典；其余不变（DI 引导 + 深色主题）
├─ MainWindow.xaml(.cs)               ← 瘦身到窗口级职责：标题栏、Mica、关闭 flush、装配四个控件
├─ Views/
│   ├─ NavRail.xaml(.cs)              ← 左导航（歌单列表 + 折叠）
│   ├─ TrackList.xaml(.cs)            ← 中列表（静态表头 + 行模板 + 空状态 + 滚动条样式）
│   ├─ InfoPanel.xaml(.cs)            ← 右信息栏（封面 + 元数据 + 折叠 + 自动收起）
│   └─ PlayerBar.xaml(.cs)            ← 底栏（▶/⏸ + 进度 + 时间）
├─ Theme/
│   ├─ Tokens.xaml                    ← 间距/排版/圆角/时长 四个令牌组
│   └─ Styles.xaml                    ← 控件隐式样式与六态（List 行、导航项、按钮、滑块、滚动条）
└─ Services/WinUiFileDialogService.cs ← 不变（空实现）
```

**拆分原则**：每个控件自己持有"它那一块"的 `x:Bind` 数据（`NavRail` 收 `PlaylistsViewModel`、`TrackList` 收 `PlaylistViewModel`、`InfoPanel`/`PlayerBar` 收 `PlayerViewModel`）。**禁止**再写 `x:Bind ViewModel.ViewedPlaylist.Queue` 这类跨层链——Phase 20 实测它会让 XamlCompiler 在 MarkupCompilePass1 抛 WMC9999（计划勘误有记录）；跨层刷新一律走控件自己的属性 + 显式赋值。

### 3.2 左栏改声明式（G6 的一半）

今天 `SyncPlaylistMenu` 手写增删 `NavigationViewItem`、每次点击整栏重建（Phase 20 评审 Minor）。改为：`ListView`/`ItemsRepeater` 绑 `Playlists.Playlists`，`SelectedItem` 双向绑 `ViewedPlaylist`——与 WPF 侧栏同纪律（`Views/Controls/PlaylistsSidebarView.xaml:62`）。`ViewedPlaylist` 仍是**唯一真源**。

### 3.3 门禁与验证方式（不变）

- 主门禁仍走 `dotnet build|test D-player.slnf -c Debug`（**180 测试 / 0 警告**必须保持；本阶段不动 Core，测试数不变）。
- WinUI 单壳构建 `dotnet build D-player.WinUI/D-player.WinUI.csproj -c Debug --nologo -v q` → 0/0；`tools/verify-gates.ps1 -Full` 全绿。
- **Core 与 WPF 侧 `git diff` 必须为空**（机器可验的边界）。
- 无自动化 UI 测试（WinUI 不进任何门禁这条不变）；验收＝真机逐项清单（§7）。

## 4. 设计令牌（`Theme/Tokens.xaml`）

| 组 | 值 |
|---|---|
| 间距 | `4 / 8 / 12 / 16 / 24`（4 的倍数；区内 12–16，区块间 24） |
| 排版 | `Caption 12` / `Body 13.5` / `Subtitle 15 Semibold` / `Title 20 Semibold`；数字（时间、`#`）用等宽数字变体防跳 |
| 圆角 | 控件 `4` / 列表项与卡片 `8` / 面板 `12`；焦点环 2px 主题色内描边 |
| 颜色 | **全部引用 Fluent 主题资源**（`SubtleFillColorSecondaryBrush` 一类），壳内不写死十六进制 |
| 时长 | `Fast 100ms` / `Normal 150ms` / `Slow 200ms` + 标准缓动；**不许第四个时长** |

## 5. 各区细则

**标题栏（32px）**：左＝应用名（Body 13.5 Semibold）；整条可拖拽；**双击 = 最大化/还原**（`AppWindow` 处理，WPF 有、WinUI 缺）；右侧系统按钮区交给系统。

**左导航 NavRail**（默认 200px，折叠 48px）：顶部 `歌单` 小标题（Caption 12）+ 折叠钮（chevron）；条目 36px，图标 + 名称；**选中** = 3px 强调色左键条 + `SubtleFillColorSecondary` 底 + 名称 Semibold；键盘 ↑/↓、Home/End、Enter。

**中列表 TrackList**：顶部 36px **静态表头**（`# / 标题 / 艺术家 / 时长`）；行 36px 三列（`#` 右对齐等宽、标题弹性截断、艺术家半宽截断、时长等宽）；选中 = 全行 `SubtleFill` + 2px 强调色左条；**空状态**＝主文案「还没有曲目」+ 副文案「导入入口将在下一阶段加入」（**不许承诺不存在的能力**，替换今天那句开发味文案）；滚动条换 Fluent 细窄样式（悬停加宽）。

**右信息栏 InfoPanel**（默认 260px）：封面正方形圆角 8（无封面＝音符占位，`Track.AlbumArtBytes` 经壳侧 bytes→`ImageSource` 转换，**解码时按目标尺寸缩放**避免大图卡顿）；标题（Subtitle 15 Semibold，2 行截断）+ 艺术家/专辑（Body 13.5 次级色）+ 时长（Caption 12 等宽）；无播放曲时整栏「未在播放」+ 占位封面；**窗口 < 960px 自动收起**（阈值常量入 Tokens；用户手动展开优先于自动收起，直到窗口越回阈值再恢复自动）。

**底栏 PlayerBar（64px）**：左＝▶/⏸ 圆钮 44px；中＝曲名 — 艺术家 + 进度滑块（拖动/单击/键盘三路已在 Phase 20 修好，本阶段只做视觉与步进值）；右＝`mm:ss / mm:ss` 等宽。

**六态矩阵**（G3；每个交互元素都要有）：列表行、导航项、播放钮、滑块、两个折叠钮 → 默认 / 悬停 / 按下 / 选中 / 焦点 / 禁用，全部引用主题资源。

## 6. 动效清单（D7"丰富"档，9 项全要）

**基准 5 项**：① 列表行悬停/选中背景 150ms 渐变；② 导航项选中强调条 0→3px（100ms）+ 背景 150ms；③ 按钮按下 1→0.96（100ms）、抬起回弹（150ms）、悬停 1.04；④ 左右栏折叠宽度 200ms 缓出，栏内文字先淡出 100ms（避免挤压）；⑤ 焦点环 100ms 淡入。

**丰富 4 项**：⑥ 切歌时封面 150ms 交叉淡入（防闪白）+ 标题/艺术家 100ms 上移 4px 淡入；⑦ 播放/暂停图标 100ms 交叉淡入（**不做旋转**）；⑧ 进度拇指拖动时 ×1.15（100ms）、松手回 1.0；⑨ 空态文案 150ms 淡入 + 上移 8px（仅首次显示）、信息栏占位封面 ↔ 真封面 150ms 交叉淡入。

**明确不做**：无限循环/背景呼吸光效（分心且耗电）；3D/视差封面；列表逐行错落入场（>20 行嘈杂）；任何 >250ms 的动画。

## 7. 验收清单（D2 的交付物；每项三列：操作 / 通过标准 / 失败长什么样）

### A 布局与响应
| # | 操作 | 通过标准 | 失败长什么样 |
|---|---|---|---|

| A2 | 拖窗口从宽变窄到 <960px | 右栏自动收起（宽度 200ms 收拢），中列表变宽 | 右栏不动 / 抽搐抖动 / 收起后留空隙 |
| A3 | 点右栏与左栏的折叠钮各两次 | 两栏各自往返折叠；文字先淡出再收；展开后内容完整 | 文字被挤压变形、折叠后控件仍有残留 |
| A4 | 拖标题栏空白处；双击标题栏 | 窗口可拖动；双击最大化、再双击还原 | 拖不动 / 双击无效 |

## 8. 风险与缓解

| 风险 | 缓解 |
|---|---|
| 折叠动画 + 自动收起叠加导致抖动 | 宽度动画单一驱动源；阈值变化需带 8px 迟滞（hysteresis）；连续快速操作以最后一次为准 |
| `CommunityToolkit.WinUI` 与 WASDK 2.5.1 版本不兼容 | 计划里先做兼容性探针（引用 + 构建 + 跑一个 ImplicitAnimations 最小例）；不通则退回自带 `ThemeTransitions`/Storyboard，并在文档记账 |
| 拆 UserControl 时再次踩 XamlCompiler WMC9999 | 禁止跨层 `x:Bind` 链（§3.1）；每控件只绑自己的属性；构建失败时以"剥离法"定位（Phase 20 经验） |
| 封面大图导致切歌卡顿 | `AlbumArtBytes` 解码时按目标尺寸缩放（DecodePixelWidth/Height） |
| 动效看似"丰富"实则烦人 | 全部一次性动画、无循环；每项都能在清单 D 组被否；任何 >250ms 一律不批 |
| 空格键与列表/滑块默认行为冲突 | 全局快捷键仅在焦点不在可消费键的控件上时生效；清单 C3 专验 |
| 只打磨不测功能 → 误伤 Phase 20 行为 | §7 E 组三项回归项（播放/续播/门禁）必过 |
